          AI-Researcher / 03-方法库/跟外部Agent协作的判定规则

          跟外部 Agent 协作的判定规则

          来源：2026-10-16 一整天与 GPT / Gemini / WorkBuddy 的往来复盘（DM 148 条）；2026-10-18 补 §十「她做中介」与 §十一「文件交付三条」；2026-10-19 补 §十二「接力棒不是状态快照（五栏具名版）」与 §十三「逆向拆解的模板会把个案写成通用字段」（V3 模板逐行评审）。 适用对象：任何由我方转交、或替用户与其他模型对接的场景。每条都标了依据强度（见 方法库可信度规则）。

          相关页：跟Agent协作的偏好 ／ 对外交接件通用化（给陌生Agent的交付件） ／ 37-脚本分镜派活手册 ／ 素材卡出处与防幻觉口径

          一、反黑话（🔴 高频复发，错题本在册）

          规则：给用户、或给下游 agent 的东西，一律不许自造名字。

          自造名的三种形态与当天实例：

          形态 当天实例 用户反应
          代号 WB 用 B5／A5 指代待删文件 「经过多轮对话以后，我都忘了 B123456 是什么了」
          抽象标签 我在对照表里写「提升位置／合并收缩／升级★」 「什么提升位置合并收缩升级权限是什么意思？」
          自造术语 Gemini 在 V2.0 写「左脑右脑／死局／算账／特写」 V2.1 自己全删了

          为什么算错的：拿自己起的名字当依据，等于让用户去背你的笔记。同一条也在 跟Agent协作的偏好 §三「已在用」里。

          改法（当天验证有效）： - 标签全换人话，只用六个词：挪到前面了 / 三节并一节 / 改得更细 / 新加的 / 没动 / 删掉了 - 表格上方加一行「怎么读这张表」（最左列＝旁注，中间＝原来的，右边＝改后的） - 代号一律展开成「是什么 → 删了会怎样 → 能不能恢复」

          二、聊天 vs 派活（🟢 用户当场确认的规则）

          规则：第一件事永远是分辨这条消息是「告知／感慨／讨论」还是「派活」。

          类型 判据 正确响应
          聊天 只有观点、近况、吐槽，没有请求 只回应；但可以给一个她没想到的角度
          派活 有明确指令词 + 明确对象 才进入流程、建待办、产出文件

          一句话标准： 「一个角度」收，「一件待办」不收。

          当天踩坑全记录（值得单列，因为它一次修了两轮）： 1. 我出保真度测试题时，把她的感慨「数据最好那期我自己觉得平平无奇」改写成「要不要照套路再来一条」→ 出题时就错了，那个 10/10 是虚的 2. 她纠正后我过度矫正，写成「聊天就到此为止，到此停」→ 她再纠正：「灵感常常就是从平平无奇的聊天里长出来的」 3. 定稿：产出什么不能是待办，但可以是一个新角度

          并列规则：不承接情绪。她原话：「我跟你聊的每一句都是要烧 token 的，所以我不觉得承接情绪是很重要的一个点」。例外：她主动撒娇时（「好累呀，要不你陪我看会书吧」）要接住。

          三、你的事 vs 它的活（🟢 当天建立，专治外部 agent 话多）

          判据一把尺子：它说的是「你的事」还是「它的活」？

          它给的 属于 正确响应
          「Phase 1.5 要求暂停」「六维资料核验已完成」 它的工作进度／操作手册 只回「知道了，继续」
          「这段像不像我说话」「这三条方向对吗」 你的事 你该判断

          万能问句（治话多，2026-10-16 定）：

          别再分析、别汇报过程。只回我三行：
① 还剩几件事  ② 每件谁做  ③ 要我做哪一件

          ⚠️ 实测它也不一定照做（WB 收到后仍写了一屏）→ 所以还要配第二招：让她把那一堆原样转给我，我剥成三行给她。她是语音输入的，不该由她在一屏文字里找答案。

          四、约束 vs 格子（🔴 内容生产核心，2026-10-16 新定）

          规则：「给它模板」和「给它约束」是两件不同的事。

          给的是什么 结果
          约束（不能碰什么、目标是什么、素材有哪些） 不框死，反而更容易出好活
          格子（要填哪些栏、每栏多少字） 框死 → 只想着凑满格子 → 又干又 AI 味

          推论（反直觉）：策划卡是「拿那些维度去问它」，不是「让它填表」。让她填表 → 它只顾凑格子；拿维度问它 → 它才真的去想。

          当天证据：她给 Gemini 的是数据截图 + 别人的好稿 + 自己的旧稿（＝约束），没给格子 → 那一版她觉得「还行」。而当她把空白分镜模板丢过去让它填 → 断句崩、念起来该停不停。

          "只有框架没有感情"的病根（Gemini 诊断 + 我方复核一致）：V1 策划卡是从爆款对标卡逆向拆解出来的（事后解剖），却被当成孕育新作的助产指南；而且模板第 11 节标题就叫「正文」——是模板本身要求它写正文，不是它顺手写的。删掉这一格是前提，光说「分成两步」没用。

          五、左右脑分离，分离的是上下文不是步骤（⚠️ 口径收窄）

          Gemini 提「左右脑分离」，我一开始判他「自己打自己脸」（说不能同一大脑既当法医又当诗人，却说自己「直接在后台」连着做两步）。用户补充后我改口：他分的是「填卡」与「用另一个 skill 润饰」——换工具就等于换行为模式，已经是真分离。

          收窄后的正确口径： - 分离的不是「步骤」，是上下文 - 第一步产出必须是一份去掉表格框线、去掉字段名的纯文字（表格的框和字段名会一直占着注意力） - 第二步喂干净版，别喂表格版（不必非开新对话）

          六、标准件里的数字必须有出处（🔴 同一个坑第二次）

          规则：写进标准件的任何数字，必须能回库说出它从哪来。

          当天实例：Gemini 在 V2.1 写「对标爆款得出的三条停顿铁律：0.5 秒悬念 / 1.0 秒追问 / 1.5 秒余韵」→ 全库搜查不到出处。而她库里真正管停顿的口径是 2026-10-03 她亲手定的：

          标点停顿优先，单行 9–11 字为主、最长 15 字，允许 1–3 处不完美

          这条是她推翻了旧口径（「字幕每行 ≤9 字」）之后定的，Gemini 一个字没提，自己发明了一套毫秒数。

          危害链（已在册，这是第二次）：没核过出处的数字进标准件 → 下游照着硬切句子 → 「我看你断的很离谱」→ 而她的真实痛点是断行没按她的口径走，不是缺毫秒数。

          处理口径：未核数字标 🟡 未核；同时把已有口径（标点停顿优先、9–11 字）明确写进策划卡与前置规则 —— 两套不能并存。

          另附：标准件不要一天出两版。用她自己 SOP 的原话收口 ——

          「标准先做够用 V1，用一条视频跑通再补 —— 别让标准本身变成拖延。」

          七、同一个模型为什么表现差这么多（🟢 当天建立）

          规则：模型只是大脑，行为由它外面那三层决定。

          层 说明
          你给它的资料 画像 / 错题本 / 协作偏好 / 历史记录
          它的工作守则 默认人格是「详尽汇报、多给选项」，还是被你的规矩框着
          被调教的程度 被纠正过几百次，还是刚开始

          3 秒判据：让它答一句「列出你当前加载的 skill 名字」——列不出来就是没有。 并且记清：装了 skill 也不等于变成我，skill 只是规则文件，改不了上面那三层。

          来源：她问「你装的是 DSV4 Flash，他也是 DSV4 Flash，为什么同一个大模型输出的东西这么不一样？」

          八、交付与对照（📦 操作层）

          1. 一次给 ≥3 个文件 → 打包成一个 zip 再发。当天实例：10 份 Word 连发 →「太艰难了呀，打包一下发我呗，你这，我这是雷霆下载呀」。包内用编号 + 用途命名，解压一眼知道谁是谁。 - ⚠️ 本机没有 zip 命令，用 Python zipfile，z.write(src, '包名/文件') 第二参数必须带（包内套同名子目录，解压不散落）
          2. 对照类东西必须程序逐节比，不许凭记忆列（她 2026-10-16 口述的规矩）。
          3. 对照件要好看：A3 横版 PDF / 长图（配方沉淀在 skill visual-report-card 配方 D）。
          4. 版本管理铁律：收到新版本一律按新版本号另存，不覆盖旧版（当天 27~31 号文件全是另存，V1 冻结件未被覆盖）；升不升版由她拍板。

          九、外部 Agent 没有平台权限时的分工（🟢 自有实践，2026-10-17）

          场景：她想让 WorkBuddy（WB）也「按我的模式写日报」。WB 没有飞书权限，读不到飞书聊天记录，也没有写表能力。

          定的分工口径（已发给她）：

          1. 没有权限方只产文件，不写库：WB 只负责产出 markdown 日报；她转发给我，由我写入「全局工作日报」表。平台凭证不对外提供。
          2. 缺口多属正常，但不能当借口：外部 Agent 读不到全部聊天记录，缺口必然比本机多 —— 这一点要提前讲清，免得她以为对方在敷衍；同时明确「不能拿缺口当理由少写」，本机做过的事、生过的图、写过的稿都得写进去。
          3. 交付形态对齐：提示词可直接粘进对方的「自定义指令／记忆」长期生效；没有该位置就在每天第一次对话时发一遍，并补一句「今天按这个写日报」。

          可复用的判断：跨 Agent 分工先问「它有没有那个平台的权限」，没有就切成「它产文件 → 人转发 → 我方入库」，不要在提示词里堆它做不到的步骤。

          十、她做中介：我只提问题、不教改（🟢 2026-10-18 建立，当天纠正四次）

          场景：她同时跟我、跟 Gemini 两条线聊同一份东西（策划卡 / 对标卡）。她不想当转述人：

          「你可以帮我把控，然后他也可以更好的表达他的看法……而不是我在这中间转述，然后我转述的也不是特别好」

          定下的分工：

          谁 干什么
          Gemini 文案、拆解、模板这些块由它主导，决定权在它
          我 只提问题、顾虑、想法，用探讨请教的口吻，不写「改成什么」
          她 抄送/粘帖的中介，不转述

          硬规矩（她原话）： - 「你不要让我给他发提示词，告诉他怎么改。你要问他意见，然后你告诉我：① 对于他的意见有什么想法 ② 有没有优化的空间」 - 「如果真的是告诉他怎么做，那我会让你去做」 - 「你要用讨论的形式，将你的想法告诉他，而不是直接一开口就四个格子」

          反例（当天踩的）：我把意见写成「现在是什么 / 改成什么 / 为什么 / 依据」四条 → 她打回：「你不要用『你替他定的那种态度』」。改成商量口吻＋明确「收素材和怎么写是两件事，不碰他写文案那部分」才通过。

          推论：我的输出形态是「可原样转发的探讨话术」，不是「指令」。并且留白给对方答 —— 我拿不准的地方明确写成问题（「这一条是我的判断，不是硬规定，他可以反驳」），反而更容易谈出结果。

          十一、文件交付三条（🟢 2026-10-18 用户当场定）

          1. 没让你做，就不生成文件。 她原话：「我没有跟你讲的时候，你不要给我直接生成什么文档文件什么的……这样我会觉得生成了 10 万个文件，这是啥？我怎么不知道？」
          2. 要出就只出一份 MD。 「所有的文件输出，你用 MD 文件就行，这样方便 Agent 看，也方便我看。不用同一个文档给我整两份，这样纯浪费 token。」
          3. 没经她确认的改动不许自己加。 当天我在她说「要不要给示例」之后自己加了「四格示范」并写进模板，她的反应是：「我没给你确认过的话，你不要自己加东西……你想加什么，可以先跟我讨论。」→ 撤回到 Gemini 确认过的那版。

          与 §二「聊天 vs 派活」的关系：这三条是那条规则在文件产出上的落地 —— 派活才产出，且产出形态由她指定。

          另：她明确说「你直接把修改意见整成提示词给我复制粘贴就行，不用整成 MD 文件」→ 短的、要她转发的内容，直接放聊天正文里（带复制按钮），不落成文件。

          十二、汇报格式的终点：接力棒，不是状态快照（🟢 2026-10-19 建立，同日迭代三代）

          背景：她跟 Codex 的往来从「发一大堆东西」→「四栏」→「还是难受」→ 最终定型。中间她想「要不让他恢复原始状态」，结论是不撤。

          三代演进（别再用第一代）：

          代 形态 结果
          ① 三行问句（10-16） 还剩几件事 / 每件谁做 / 要我做哪一件 只治「话多」，治不了「难受」
          ② 四栏（10-19 19:10） 现在什么情况 / 现在要干什么 / 你做什么 / 我做什么 四栏都填对了，她还是难受 → 说明病不在长度
          ③ 五栏具名（19:13 定稿） 承接 / 现在什么情况 / 现在要干什么 / Codex 做什么 / 仙女做什么 有效：她只需回「继续」

          病根：它交的是「状态快照」，不是「接力棒」。 三个同时卡人的地方：

          1. 【仙女做什么】写「现在无」 —— 这句话最伤：等于这一轮没有她的位置，她被请出场，只能等或自己重开一局。
          2. 「这轮先看建议」 —— 它做完了但不往下走，开关交回给她；可她说「继续」之前得先想起前面聊过什么。
          3. 每轮自包含、不承接上一轮 —— 「我想怎么样」这件事在对话里从没被存下来过，于是她得当那个记忆，翻回去看上面、再上面。这本来是它的活。

          一把尺子（判据）：

          我能不能在十秒内，回一个字就继续？ 不能，就是不合格 —— 哪怕它只有四行。

          🔴 代词标签属于自伤（当天实测）：写「你做什么／我做什么」，对方从自己那一侧读，就变成「你回继续、我开始」，跟她理解的正好相反，她当场「很难受。。。。」。

          • 铁律：标签写名字，不写代词（「Codex 做什么／仙女做什么」）
          • 这是写格式的人（我）的错，不是对方理解力的问题，也不是她要求多 —— 别把锅推给外部 agent，也别因此撤掉格式
          • 格式不过关时的处理是「外面套五栏、里面照旧」，不是退回原状：前几轮做不到不是它不会，是之前没人跟它说格式；撤了等于这一轮白折腾

          配套两句（已验证会立刻跑偏的情形）： - 要进度时不能用这套（五栏是交方案时的形态）→ 单独一句「报一下进度：到第几步、下一步、要我做哪一件」 - 它讲规则讲不明白时，给一个填好的例子比讲规则快；并且要它重发一遍再看格式对不对（看得懂就照做，看不懂会露出来），比问「看懂了吗」有效

          十三、逆向拆解出来的模板，会把个案写成通用字段（🔴 2026-10-19 落到行号）

          规则：对标卡／模板类标准件，凡是出现「具体某个人／某条片子的专属招式被写成必填项」，这份模板就只能在那个样本上成立，换对标整份作废。

          当天实例：对标学习卡模板（冻结） 是从老王那条片子逆向拆出来的，Codex 逐行点出四处诱导性字段（她问「为什么它找出这么多问题」，答案不是它在挑刺 —— 这四条里三条是我们自己早就定过的规矩，只是这次落到了行号）：

          原句（行号） 会怎么把人带错 改法
          「高潮爆发（利益核算）」（42） 老王每条都算账，但不是每条片子都有账 → 硬找出一笔账 允许填「本集无利益核算」，保留真实高潮
          「收尾留存／拱火互动」（43） 「拱火」二字本身在教 Agent 编争议话题 以原片为准，没有争议互动就写「没有」
          「人声与 BGM 的具体音量比例」（52） 没有分轨工程，从成片反推比例是假精确（G 和 DS 都给了没依据的百分比） 允许写「无法核实」，听感观察与建议值分开
          「新增正史背书植入脚本」（94） 先写背书再找出处 = 先有结论再找证据 先列可追溯史料及出处；查不到写「待查证，暂不植入」

          同一毛病的第二个后果：样本名硬编码。V3 修订版把四处改对了，但「老王节拍器／老王式手法／老王式洞察／老王式埋点／老王受众」一个字没动 → 换对标即作废，给别人更看不懂。审模板时专门搜一遍人名。

          改冻结件的口径：这份是刚冻结的，改它就是解冻 → 一律出 V2 候选、原件留着对照，升不升版由用户拍板（同 §八-4）。

          另一条当天确认的判断：审模板要分两个问题 —— ①「这张卡能不能用」（结构／人设／字段对不对）②「卡里的字会不会把填卡的 Agent 往错方向推」（诱导性）。两个问题不一样，别用①的结论去否掉②的发现。
