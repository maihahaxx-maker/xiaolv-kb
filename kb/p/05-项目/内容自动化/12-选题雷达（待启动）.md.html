          📡 选题雷达（规划中 · 待启动）

          状态：2026-09-30 记录想法，明确暂缓。 启动条件 ＝ 拉瓦锡 V3 交付并发布之后。 暂缓理由（用户当场认同）：现在同时开"改稿"和"搭采集系统"两条线，大概率两边都是半成品。

          一、用户的顾虑（2026-09-30 原话）

          "第一批选题是豆包帮我生成的……我是个化学老师，这东西做给学生看确实还行。 但如果基于流量去考虑，你不得参考当时的热点吗？不然就是埋头苦干， 你选了一大堆你觉得 OK 的东西，但别人不爱看。"

          这个顾虑是对的，而且比"要不要装采集 skill"重要得多。

          二、把"热点"拆成三层（关键，别混）

          用户的直觉对，但"热点"这个词混了三件事。正确顺序是 1 → 2 → 3：

          层 参考什么 回答的问题 现在有没有
          1 人物层 这个人在平台上被讲了多少次、数据多少 选谁？ ❌ 空的（豆包选题没有数据支撑）
          2 角度层 同一人物，哪些角度没人讲过 / 讲烂了 讲哪一面？ ❌ 空的
          3 时机层 时事 / 剧集 / 新闻带火某人物时的窗口期 什么时候讲？ ❌ 空的

          结论：用户说要"参考热点" —— 三层其实都要，但第 3 层（时事热搜）排最后。

          历史人物故事是常青内容：微博 / 百度热搜那种"新闻热点"，对它的帮助 远小于"人物热度榜"。要的是"同类爆款选题榜"，不是"热搜榜"。

          最关键的一句（用户 2026-09-30 认同）：

          选题决定天花板，文案决定你能不能碰到天花板。 冷门人物（如沈括）文案写得再好，天花板就在那儿；热门人物（如秦始皇）文案一般也有基础流量。

          豆包选题的问题不在"没追热点"，在"没有数据源" —— 它靠模型印象选人，不知道 哪个历史人物在视频号 / B站上真的有人看。第 1、2 层都是空的。

          三、额外提醒：差异化从"角度"来，不从"人物"来

          走"热门历史人物"路线的风险：热门人物 ＋ 零粉丝 ＝ 最激烈的正面竞争 （开卷见河山、观史之臣都有几万到几十万粉，我们是 0）。

          → 建议切法：人物选热门的（拿流量），角度切独家的（拿差异化）。 例：讲秦始皇不选"统一六国"（讲烂了），选"他为什么不立皇后"。

          四、待启动方案（2026-09-30 起草，未实施）

          每天 08:30（错开已有的 8:30 雪见清单）
  → B站搜「历史人物 / 科学史 / 文明史」关键词，取近 30 天
  → 按播放排序，抓：标题 / 时长 / 播放 / 收藏 / 账号
  → 生成《选题雷达表》：一行 = 一个"被讲爆的人物 ＋ 数据"
  → 喂进《样本对照总表》的「待拆区」
用户只需要：看到感兴趣的，说一句"拆这条"

          五、技术现实（别抱幻想）

          平台 能不能自动抓 说明
          B站 ✅ 可以 搜索接口公开，历史人物类爆款重镇
          知乎 ⚠️ 额度低 热榜 2 / 搜索 10 次每天（未实名档）
          百度热搜 ✅ 可以 但那是"新闻热点"，非选题热度
          抖音 / 小红书 ⚠️ 半自动 反爬，需 cookie / API
          视频号 ❌ 不行 无公开热榜、无账号目录，封闭生态

          → "每天自动扒视频号热点"做不到。 视频号数据只有两条路： ① 用户转发链接给我解析（已跑通）；② 雪见群那套服务（别人的基础设施）。

          六、不装第三方 skill 的理由（2026-09-30 调研）

          搜过 skills.sh / ClawHub，现成的热榜类 skill（cn-hot-trends-6、hot-topic-tracker、 hot-topics-daily、hot-aggregator-cn）全部不覆盖视频号，且抓的是"热搜榜"不是"选题热度"。

          → 结论：不装第三方 skill；B站抓取自己写脚本（更可控、零 API key、输出格式由我们定）。
